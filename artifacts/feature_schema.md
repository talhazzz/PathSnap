# Shared candidate-feature schema

Generated by `ml/preprocessing/build_shared_dataset.py` from `data/raw/Student folder/train/` only. Source files are whitespace-delimited, without headers:

- `.track`: longitude, latitude, time-like value (observed values increase over time; rows are GPS observations).
- `.nodes`: longitude, latitude; node IDs are zero-based row positions.
- `.arcs`: directed `from_node_id`, `to_node_id`; arc IDs are zero-based row positions.
- `.route`: ordered arc-row IDs indexing `.arcs`; verified by in-range references and directed endpoint continuity. Route sequence length differs from GPS count, so labels are not based on row alignment.

## Shared output columns

| Column | Type | Meaning | Model input? |
|---|---|---|---|
| `trip_id` | string | Source training trip identifier; group/split key | No |
| `point_idx` | int | Zero-based row index in `.track` | No |
| `candidate_arc_id` | int | Zero-based row index in `.arcs` | No |
| `split` | category | Trip-level `train` or `validation` assignment | No |
| `label` | int | 1 for the route arc matched to this GPS observation, otherwise 0 | Target |
| `distance_m` | float | GPS-to-candidate directed-segment distance | Yes |
| `signed_lateral_offset_m` | float | Signed perpendicular offset relative to directed segment | Yes |
| `projection_fraction` | float | Clipped projection position along candidate arc, [0, 1] | Yes |
| `distance_to_arc_start_m` | float | Projected along-segment distance to start | Yes |
| `distance_to_arc_end_m` | float | Projected along-segment distance to end | Yes |
| `arc_length_m` | float | Candidate directed-segment length | Yes |
| `candidate_rank_distance` | int | Zero-based rank by GPS-to-segment distance for the point | Yes |
| `candidate_count_at_point` | int | Number of retained candidate arcs for this point | Yes |
| `is_nearest_candidate` | int | 1 when the candidate has the smallest segment distance | Yes |
| `is_within_search_radius` | int | 1 when distance is within configured candidate radius | Yes |
| `gps_step_distance_m` | float | Distance from this observation to previous GPS observation | Yes |
| `gps_speed_mps` | float | Previous-step distance divided by time-like-field delta; zero if unavailable | Yes |
| `time_delta_s` | float | Difference in the third `.track` column from previous point | Yes |
| `gps_bearing_valid` | int | 1 when prior displacement and positive time delta exist | Yes |
| `heading_alignment_cos` | float | Cosine of GPS heading minus directed arc bearing; zero if unavailable | Yes |
| `heading_alignment_sin` | float | Sine of GPS heading minus directed arc bearing; zero if unavailable | Yes |
| `is_self_loop` | int | 1 when directed arc length is below 0.01 m | Yes |

The 17 model input columns are listed in the same order in `ml/preprocessing/build_shared_dataset.py` as `FEATURE_COLUMNS`. Never train on `trip_id`, point/arc identifiers, or `split`. Split at the trip level; do not randomly split candidate rows.

## Label method and limits

`.route` references are interpreted as ordered indices into `.arcs`. A dynamic-programming alignment maps GPS observations monotonically to that route sequence using point-to-segment distance as its emission cost and a small penalty for advancing multiple route arcs between adjacent GPS observations. This explicitly avoids assuming GPS rows align with route rows. A GPS observation is retained only if its matched reference route arc is within the configured 45 m confidence limit; the exact matched arc is included as a candidate if needed. Other retained candidates for that observation receive label 0. This is a route-derived proxy target, not a manually audited ground truth; excluded points and per-trip alignment distances are reported in `artifacts/shared/shared_pipeline_summary.json`.

Candidate search uses a 60 m radius, retaining at most 16 closest arcs before ensuring the matched reference is present. If a point has no in-radius graph arc, its nearest graph arc is included and flagged by `is_within_search_radius`.
